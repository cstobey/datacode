# DataCode implementation plan

Written for one senior Haskell developer who has read `docs/` and `review/00-report.md`. Eight area plans were reconciled into this; where they disagreed, the resolution and its reason are stated inline. Sizes are engineer-time guesses, not commitments.

---

## A. The shape of the effort

DataCode is three systems that happen to share a repository: a compiler front end for a layout-sensitive, name-resolution-dependent schema language; a single-node storage engine with its own log format, index set, and maintenance queue; and a replicated, sharded distributed database with a cross-shard commit protocol. The front end is not a veneer over the engine — it is roughly a third of the work, because the schema *is* data, so the elaborator's output is a stored, content-addressed, replicated object rather than an internal artifact. The genuine difficulty is concentrated in four places, and only one of them is where a database usually hurts. First, elaboration: `spikes/functor-dsl` proves the effect-indexed GADT works as a *representation*, but every term in it is Haskell source, so GHC's typechecker did the index reconstruction that a runtime elaborator must now do with existentials, singletons for `Eff`, and a `Sub` witness that cannot be a class dictionary. Second, the query engine: no spike touches it, `Ty` has no `Table a` constructor, and `group`'s generated `rows` column has no type — and this is the largest single subsystem and the home of most of the sixteen settled syntax changes. Third, distributed correctness: `review/00-report.md:1043-1075` records that the prepared-node protocol has no validation phase at commit, and every bug of that class is an interleaving that only a deterministic simulator will reproduce. Fourth, and most corrosive to schedule: about twenty system tables and twelve types are load-bearing and undeclared (structural defect 6), so several subsystems cannot be *started* until someone writes a `.dc` file that does not exist.

What is genuinely de-risked is the substrate and the term representation, and both matter: the log format, the mmap read path, the LMDB threading fix, big-endian key ordering, HTTP dispatch, and the functor DSL's shape are all measured facts rather than intentions. That buys real speed in milestones 3 and 4 and almost nothing after. Honest total, for one experienced developer: roughly 45–60 engineer-months. Milestones 1–8 — a single-node system that is unmistakably DataCode, survives `kill -9`, serves HTTP under auth, and swaps generations under load — are about 27–32 of those. Distribution is another 10–14 on top, and it is the part where every settled decision is only testable under conditions no current harness produces. Solo, that is four to five years. With three people taking the parallelism marked in section C, about two and a half years to the end of milestone 8 and three and a half to the end of milestone 9. There is no version of this that is a year's work, and the estimate should be re-derived after milestone 1, because five of the seven probes there can move it.

## B. Package layout

`docs/tech-stack.md:191-196` proposes five packages. Take seven libraries, two executables, and a test kit. Three changes to the proposal, each with a reason:

- **Split `datacode-storage` out of `datacode-core`.** The C dependency (`liblmdb`) must not be on the build path of the linter, the formatter, the elaborator, or the analyses. That is what makes `datacode check` and `datacode lint` runnable in CI, in an editor, and in this repository's own sandbox, which cannot build a new Hackage dependency at all (`$HOME` is read-only; verified this session).
- **Add `datacode-wire`.** The Cap'n Proto swap must be isolated behind an accessor API from day one (see risk R11), and both the server and the thick client need frames. A sub-library inside storage would put the client behind LMDB.
- **Drop `datacode-html`; add `datacode-testkit` and `datacode-handlers`.** HTML rendering is post-MVP (`tech-stack.md:62`) and its first real consumer is a format functor in the server. The test kit holds generators, the model, and the cluster simulator — it is a library other packages' test suites import, not a test suite. `datacode-handlers` is separate because the generation-swap topology ships it as a distinct binary and because the missing `Effect → Tx` lift is enforced by *not exporting a constructor*, which is a package boundary, not a convention.

| Package | Owns | Depends on |
|---|---|---|
| `datacode-core` | `DataId`/`Ordinal`/`HeadKey`/`TxPosition`, Crockford base32, order-preserving byte encoding, value carriers and `Ty` witnesses, `Moment`/`Duration`/`Period`/`Grain`, `Error`, `Outcome` | base, bytestring, text, time, containers, vector, scientific |
| `datacode-wire` | Frame layout, length prefix, checksum, `TxNode` and row payload **accessors**; `cereal` implementation now, Cap'n Proto later | core |
| `datacode-schema-dsl` | internal lib `syntax`: lexer, layout pass, CST, parser, printer, diagnostics.<br>public: resolver, schema graph + content addressing, traits and effective field set, keys and placement, elaborator, `Term` GADT, structural analyses, interpreter | core (+ crypton) |
| `datacode-storage` | LMDB envs and dbs, extents, mmap/`pread`, `head_index`/`log_index`/`version_index`/`fk_index`, commit path, recovery, maintenance queue, arrangements | core, wire |
| `datacode-engine` | Field-write pipeline (steps 1–8), query planner and streaming executor, mutation and write-through, materialization, enforcement modes and violations, `Session` interface | core, wire, schema-dsl, storage |
| `datacode-server` | Warp/Servant frame, route trie, auth, request log, generated and custom routes, `File` octets, scheduler, replication, epochs, cross-shard, connectors | engine |
| `datacode-handlers` | `Effect`, capability newtype (constructor unexported), handler pool, SMTP/HTTP handlers | core, engine (interface only) |
| `datacode-client` | Wire envelope, connection, TLS, remote `Session` backend | core, wire |
| `datacode-cli` (exe `datacode`) | REPL, formatters, cursor rendering, admin commands | client, engine |
| `datacode-testkit` | `SchemaRecipe` generator + model, golden harness, deterministic cluster simulator | all (dev only) |

Edges are acyclic and one-directional: `core → wire → {schema-dsl, storage} → engine → {server, cli}`. `schema-dsl` must never depend on `storage`; if it starts to, the linter has grown a database.

## C. Milestones

Ten milestones. The system is runnable at every one. `‖` marks units that can proceed in parallel with a different person.

### M1 — Probes, decisions, and a frozen grammar
**Delivers** seven recorded verdicts and one EBNF an implementer can code against. Everything downstream reads both.

| Unit | Notes |
|---|---|
| P1 mmap reader visibility ‖ | Three threads: one holding lazily-consumed mmap'd slices, one zeroing the region as `scrub` does (`storage.md:104-118`), one appending and re-mapping. Count torn reads and SIGBUS (the GHC RTS does not convert SIGBUS to an exception, so a hit is a process death). |
| P2 LMDB under GHC threads ‖ | `MDB_NOTLS` on/off, 64 `forkIO` readers against one `forkOS` writer for 60 s under `-N4`; then five environments open concurrently in one process. Starts from `spikes/capnproto/src/Spike/LmdbFixed.hs` unchanged. |
| P3 Elaboration ‖ | Encode ~15 functors from `Spike.Schema` as a first-order `Term'`, write encode + typechecker returning `SomeTerm ctx` with `ctx` fixed per functor kind. Replace `class Sub` with a GADT witness first. |
| P4 Query in the GADT ‖ | Add `TTable`, encode `Order >< Customer as c { Order.*, c.name as buyer }`, a `group` with `count rows`, and a write-through insert. Report whether `sameTy` and the de Bruijn context survive. |
| P5 Assert read-path cost ‖ | Wire `spikes/functor-dsl`'s `Deref` to LMDB, run the 3-hop `memberAccess` over 100 k rows, compare against a hand-written semijoin. |
| P6 Wire route ‖ | Decided already: `capnp-0.18.0.0` requires `ghc-prim <0.11` against the shipped 0.12 and does **not** solve on GHC 9.10.3 (verified this session; `lmdb`, `mmap`, `cereal`, `megaparsec` all solve clean). Confirm and choose: pin GHC 9.6, patch the binding, or hand-roll the encoder for the two struct shapes as `spikes/capnproto` already did. Recommend hand-rolling. |
| P7 MariaDB binlog decode ‖ | `mysql-haskell`'s `getBinLogPacket` does `toEnum . fromIntegral <$> getWord8` into a 36-constructor derived `Enum`; MariaDB emits event types 160–164. Twenty lines against a MariaDB 11 container decides whether CDC needs a hand-rolled packet reader before GTID is even a question. |
| G1 Grammar freeze + `datacode-ebnf-check` | The eight structural defects (`00-report.md:944-1042`) plus the `30-integrated-grammar.md` §B delta plus the parser-only items. Defect 1 is mandatory: lift "a `Query` in boolean position asserts non-empty" from `AssertBody` to every `Bool` position. |
| G2 Ambiguity report | Transcribe the frozen EBNF into a throwaway `happy` grammar and read the shift/reduce report. It is the only mechanical ambiguity detector available, and a combinator parser will resolve `Order { status = Shipped }` silently and possibly as a mass update. |

**Depends on** nothing. **Size** 4–6 weeks (all units parallel; ~10 engineer-weeks).
**Demo** `cabal run probes` prints seven PASS/FAIL verdicts with numbers; `datacode-ebnf-check docs/schema/railroad.md` exits 0 and prints the terminal inventory.

### M2 — `datacode fmt` and `datacode lint`
**Delivers** a lexer with a separate layout pass, a uniform CST, a canonical printer, and a corpus linter — the durable fix `00-report.md:1288` asks for, delivered while the 31-file doc rewrite is still running.

Units: lexer + layout (maximal munch over the corrected `:` family; two rules only — comma at body depth 0, column-0 termination; tab = 8, written down); uniform CST that does **not** distinguish `Query` from `Expr` or `Insert` from `Update` from `FuncApp`, because all three disambiguations are semantic (`railroad.md:539`, `:680`, `30-integrated-grammar.md` §B.8); `megaparsec` over `Vector (Located Token)` with `withRecovery` at the `Statement` boundary; pretty-printer ‖; fence extractor + golden harness ‖.

**Depends on** M1/G1, M1/G2. **Size** 6–8 weeks.
**Demo** `datacode lint docs/` prints `287/340 blocks parse` with file:line and a suggested fix for each failure; `datacode fmt --check docs/` asserts `parse ∘ print ∘ parse == parse` over every block that parses.

### M3 — The substrate: ids, frames, LMDB, extents, indexes, commit, recovery
**Delivers** something that behaves like a database with no language in front of it. Runs fully parallel with M2 and M4 — two people, no coupling until M5.

Units: `DataId`/`Ordinal`/`HeadKey` with `type role DataId nominal` and a persisted, fsynced high-water lease ‖; `TxPosition`/`PhysicalLocator` split (`review/10-findings.md:2021`) ‖; frame codec **with a checksum**, which `storage.md` does not have — `[len][CRC-32C over len+payload][payload]`, and every consumer written against accessors (`txTimestamp :: Frame -> Word64`), never against a decoded record, or zero-copy is lost and the wire swap becomes a month; LMDB wrapper with a rank-2 region parameter so an `MDB_val`-backed `ByteString` cannot escape its transaction, and **no** `mdb_set_compare` export ever; extents, with the active extent read through `pread(2)` and only sealed extents mapped; four indexes (`head_index`, `log_index` with a `(ExtentId, offset, length)` value, `version_index`, `fk_index`) plus `rebuild-index`; commit path (log append + fsync *first*, index transaction second — that ordering is the crash-consistency argument and is written nowhere); maintenance queue as one mechanism with three policies under an epoch fence keyed on LMDB's own reader transaction ids.

**Depends on** M1/P1, M1/P2, M1/P6. **Size** 3.5–4.5 months.
**Demo** `datacode-store commit`, `get`, `get --at <node>`, `history <id>`, `refs <id>`; `datacode-store stress --readers 64 --seconds 60`; `kill -9` mid-append then `datacode-store recover && datacode-store scan` clean; `datacode-store compact --reader-check` with a background reader asserting it never sees a torn frame.

### M4 — `datacode check`: the first recognisably-DataCode artifact
**Delivers** a schema compiler with no engine behind it, printing what no other database can print about a schema file.

Units: name resolution (blocked on decision G2 in section G — settle it before the AST is fixed) ‖ nothing; schema graph, canonical form, content address over the **resolved** node, commit diff per address; traits, multiple inheritance, effective field set with predicate origins ‖; keys, rooted-key rule, placement derivation, `next` scoping ‖; field-scoped computed types and the validation address space ‖; elaborator to `∃ e a. (SEff e, Ty a, Term ctx e a)` with `lubEff` and `subDict` written once as nine-case functions; port of `Spike.Analysis` (352 lines) plus derived-key computation, which three later subsystems read.

**Depends on** M2, M1/P3, M1/P4. **Size** 3.5–4.5 months.
**Demo** `datacode check examples/commerce.dc` prints, for the `CLAUDE.md` example schema: each table's derived key and shard root, each assert's variety and `bypass access` membership, the mixed-conjunct warning, anchoring with hop counts, shard-crossing coercions, the revalidation set with a cardinality estimate, retention-chain grain alignment, and the every-was-unnecessary classifier — reproducing `spikes/functor-dsl/output.txt` §8 from *text*. `datacode commit --file x.dc` prints a hash that is stable under reformatting and comment changes.

### M5 — Single-shard engine and the REPL
**Delivers** the first thing a person types a query into.

Units: `Session` interface with an embedded backend — **recommended departure from `cli.md:367`**, which makes the CLI shippable before the wire protocol; field-write pipeline steps 1–5 in the order `functors.md:46-68` gives (validate the plaintext, transform after, so "the plaintext never enters the log" is structural); FK resolution, `unique`, `next` allocation, and the re-key gate implemented as a *rejection* first (see risk R18); reverse-FK index and the row-level revalidation set ‖ nothing — it gates step 7; path constraints step 7; read-path access enforcement and redaction; streaming executor (`streaming`, not lazy IO, not `conduit`) — scan, filter, `:>` join both directions, outer join by guard, projection, `order by`, `limit` with cursor pagination ‖; REPL over `haskeline` with multi-line accumulation driven by the layout pass ‖; four output formats with the `100 of 100+` footer and the `next:` continuation ‖.

**Depends on** M3, M4. **Size** 4.5–5.5 months.
**Demo** `datacode --local ./db`, paste the `CLAUDE.md` commerce schema, `:commit`, insert three orders, then `Order where total > 100 order by placed_at desc limit 2` returning rows with a pasteable `next:` line that resumes correctly across a tie in `placed_at`; the same query under two tokens showing one row wholly `Redacted`.

### M6 — Query completion
**Delivers** the rest of the query language. `group` first because the segmented carrier it produces is also the wire shape and the stored-component shape.

Units: segmented nested-table carrier (one contiguous child block + `Vector Int` boundaries, at every depth) and `group` ‖; projection sub-nesting (`ProjItem ::= FieldPath Projection? NameClause?` — the one nesting rule, absorbing the withdrawn `nest` clause) and aggregates over `Table a`; `at`, sample moments, version-chain reads, `diff` as a merge-join on the derived key; mutation, write-through decomposition, tombstones, RESTRICT ‖; derived extents, arrangements, incremental refresh, `materialize`/`refresh view` ‖ (not on the correctness path).

**Depends on** M5. **Size** 4.5–5.5 months.
**Demo** `Order group { customer } { customer, count rows as orders }`; `RecentOrder` written through into two base tables in FK order; `Order diff "v2.1.0" to "v2.2.0"` projecting `before`/`after`/`change`; `materialize app.reporting.MonthlySummary` then `:explain` showing the plan change from scan to arrangement with a measured latency drop.

### M7 — The server
**Delivers** one node serving HTTP under auth, with events running. Three sub-tracks that are genuinely independent until they meet at the dispatcher.

Track A ‖ — Warp + Servant static frame + route trie (compose the two spikes; replace the `Map` with a `RouteTrie Application` in a `TVar`), version-token resolution serving two live versions from one process, request log on every path including a rejected transaction, generated CRUD, custom routes as rows, `File` octet streaming with a strong ETag and single-range `Range`.
Track B ‖ — credentials, login, `Secret`, envelope crypto, `Client`/`Registration`/`ClientToken`, grants, `bypass access` skip sets precomputed at schema commit. Independent of HTTP; test it against the engine with no server.
Track C ‖ — enforcement modes and violations (`Outcome`, not `Either Error a` — retrofitting `monitor` later touches all four functor kinds), queue traits, scheduler with aged priority, handler pool, `on`/`every` triggers, backoff, `repair`.

**Depends on** M5 (all three tracks); Track A also on M3. **Size** 5–6 months across the three tracks.
**Demo** `curl -H 'Authorization: …' localhost:8080/v1/records/app.commerce.Order` returning JSON with an access assert enforced identically to the REPL; the same table at a second version token in the same process; `datacode --exec 'insert into system.api.CustomRoute …'` while `wrk` runs, with zero dropped requests; an order set to `Shipped` and an email leaving the handler pool.

### M8 — Single-node hardening gate
**Delivers** the verdict that distribution is worth starting. Nothing here is a feature.

Units: crash recovery proven (`kill -9` mid-transaction, rebuild both LMDB index sets from the log); `verify shard … deep` locally; four-process topology and generation swap with a measured stall; router↔worker IPC (decide and measure it first — see risk R14); `show`/`cancel`/`export` with cooperative check points in the interpreter (a `throwTo` against an allocation-free scan loop may never be delivered, and a `cancel` that silently fails on exactly the queries needing it is worse than none); every peer-requiring command refusing cleanly by naming the missing peer; the ten undeclared system tables actually declared.

**Depends on** M7, M3. **Size** 2.5–3.5 months.
**Demo** a scripted drill: `kill -9` the writer mid-transaction → restart → `verify shard user.commerce deep` passes → both live version tokens still serve → `datacode-governor swap --generation N+1` under `wrk` reports the write stall → `elevate secondary db2 …` refuses with "no peer db2 configured".

### M9 — Distribution
**Delivers** a replicated, fenced, cross-shard cluster. The first unit is the harness, not the protocol.

Units: deterministic simulator — N replicas in one process, real LMDB at the storage edge, seeded scheduler, injectable partition/crash/reorder, protocols written as pure `step :: Msg -> Replica -> (Replica, [Msg])`. Build it first; it is the cheapest probe for five of the risks below, and if replication is written directly in IO over `async` and `TVar`s the determinism is unrecoverable without a rewrite. Then: routing types and the range tree (blocked on decision G4); replication fan-out with a **2-of-3 commit quorum** and an ACK that means fsynced, not received; announce-and-fetch catch-up with a piece vocabulary parameterised from the start; epochs, fencing, elevation with a majority ACK, rejoin, `recover/<shard>/<epoch>` branches; cross-shard transactions **with a certification phase**; shard directory read half ‖ (early) and write half (late); constraint shards; schema shards; distributed auth.

**Depends on** M8. **Size** 9–13 months. Runs ‖ with M10.
**Demo** `datacode-cluster-sim split-brain --seed 42` — partition the primary, a secondary elevates at epoch N+1, both sides accept writes, heal, the old primary fences itself, `show conflicts` lists one `recover/` branch. Then `datacode-cluster-sim write-skew --seed N` showing both transactions committing under the documented four-step protocol and exactly one committing under the certified one. Then the same drill on a three-process local cluster.

### M10 — Connectors and CDC
**Delivers** MariaDB replication into shadow tables. Fully parallel with M9 — different person, no shared code below the engine.

Units: re-seed from state (uses only `Database.MySQL.Base` query execution, so it is upstream of every binlog risk, and it is the recovery path regardless — build it first, per `00-report.md:509-556`); MariaDB binlog + GTID dialect; MySQL `COM_BINLOG_DUMP_GTID` dialect ‖; shadow-schema introspection and evolution ‖; the ingest scrub matcher, which is *not* deferrable because it runs before the frame is written (`integrity.md:463-465`) and is the only defence that works once bytes are in an append-only log.

**Depends on** M7 Track C, M1/P7. **Size** 3.5–4.5 months.
**Demo** `datacode --exec 'add connector mariadb "production"'`, `reseed connector mariadb.production`, then `INSERT` at the source and watch the row appear in `connectors.mariadb.production.orders` within the poll interval; restart the connector and watch it resume from its recorded GTID position.

## E. Risk register

Ordered by severity. **Bold** entries should be probed **before** the milestone that consumes them, not during it — all of them are in M1.

| # | Risk | Knowable | Cheapest probe |
|---|---|---|---|
| **R1** | **Elaboration from text to `Term ctx e a` may not be tractable in the assumed shape.** `Sub` is a class and no dictionary can be built at runtime from an `SEff`; `Lub` is a type family the elaborator must compute at the value level. If reconstruction forces an untyped runtime representation, the GADT is an artifact of the interpreter rather than a property of the schema, and every claim resting on "the effect index derives it" weakens to a check. | Now, before M4 | Two days: replace `class Sub` with a GADT witness, then encode + typecheck the 15 functors in `Spike.Schema` back to `SomeTerm ctx` with `ctx` fixed per kind. |
| **R2** | **The zero-copy read path has no reader-visibility discipline.** Relocation and `scrub` rewrite bytes under live mmap readers; a Cap'n Proto reader over a mutating buffer validates pointers lazily and yields arbitrary structure rather than failing. LMDB's MVCC covers the index only. Confirmed defect (`00-report.md:1066-1069`, Crotty et al. CIDR 2022). | Now, before M3 | One day: reader thread over a mapped frame, writer overwriting the range; count torn reads; repeat with relocate-then-flip-locator under an epoch fence tied to LMDB reader transaction ids and confirm zero. Doubles as M3's `--reader-check` harness. |
| **R3** | **LMDB reader slots against GHC green threads.** Slots are thread-local by default; a `forkIO` reader that resumes on a different OS thread reuses another's slot. Every spike ran single-threaded, so "reads run concurrently under MVCC" (`tech-stack.md:113`) is asserted, never tested. Also untested: N environments in one process, which the simulator requires. | Now, before M3 and M9 | Half a day: `MDB_NOTLS` on/off, 64 readers + 1 writer, 60 s, `-N4`; then five environments concurrently. |
| **R4** | **The query language exists in no spike, and `group`'s `rows` column has no type.** `Ty` is closed with no `Table a`; `Query ctx` carries no row type and has only `Exists`/`Count` as eliminators. This is the largest subsystem and it is on the critical path for anything user-visible. | Now, before M4 fixes the constructor set | One week: add `TTable`, encode a projection join, a `group` with `count rows`, and a write-through insert, plus the derived key for each. Highest-value single probe in the plan. |
| **R5** | **Access asserts run per row on every read, and each hop is a real storage traversal.** 0.14 µs is against an in-memory `Map`; a 3-hop assert over a 100 k-row scan is ~1.1 s of index reads at 11 µs. If the planner must hoist asserts into the plan as semijoins, the DSL must expose enough structure to be rewritten. | Now, before M4 | Two days: wire `Deref` to the LMDB store, run `memberAccess`, compare to a hand-written semijoin. The ratio is the size of the planner obligation. |
| R6 | **The revalidation set has no row-level index, no bound, and no exclusion rule**, while `enforce always` is the default. Traversing `:>` backwards is a preimage; writing one `Reference` row reaches the whole connected component. Without a fix, every absence assert is O(shard) per write, which defeats the reason anchoring exists. | Now; blocks M5 step 7 | No experiment. Decide: mandatory `fk_index`, closure restricted to edges in some assert's path, `Reference`/`Configuration` edges excluded, and coercion to `enforce forward` above a threshold. Then measure closure cardinality over a synthetic 30-table schema (3 days). |
| R7 | **The cross-shard protocol has no certification phase.** Two coordinators with mutually invisible prepared nodes both commit; the coordinator never re-checks its pin before appending COMMIT; B appends nothing on commit so the outcome is not a local fact there. ## F. Test strategy

**Property tests for the mathematical invariants.** Use `hedgehog`, not QuickCheck: a schema is a deeply nested invariant-carrying structure and integrated shrinking is the whole game — a hand-written `shrink` for it will be large and wrong. The invariants worth encoding, in descending order of how much they buy:

- **Derived-key soundness**, two ways. Against a model of the propagation table (`queries.md:449-473`, with sets not singletons, superkey reduction, FK substitution, and outer-join degradation); *and* against a generated instance, asserting no two result rows agree on the derived key. A model can be wrong the same way twice; an instance cannot. Three subsystems read this computation and are wrong together if it is wrong.
- **The effect algebra**, enumerated rather than sampled — nine cases. `Lub` associative, commutative, idempotent with `Pure` as identity; `Sub e f ⟺ Lub e f == f`. The property with real content is that a term's inferred effect equals the LUB of its subterms', which is what makes `functions.md:70`'s infer-and-check sound.
- **Clock-step invariance.** Evaluating the same term against the same store with the wall clock stepped yields the same value. This is "time is a parameter, never ambient" made executable, and it is the property most likely to catch a regression when someone adds a primitive.
- **Byte-order equals `Ord`** for every key encoding and both sort directions, extended past the locator to variable-length `head_index` keys, where a parent's key must be a proper byte prefix of every descendant's — the claim `storage.md:41-51`'s one-range-scan subtree rests on and that no spike has tested.
- **`DataId` uniqueness under adversarial clock traces** — a `[Integer]` trace with regressions, repeats and jumps; the boundary that hides a duplicate is the transition *out* of clamping.
- **The append-only census**, with `scrub` and compaction as explicit parameters rather than silent exemptions. That is the shape that would have caught structural defect 2. Add a schema-level companion: every `system.*` field is either on the declared exemption list or is never an update target anywhere.
- **Round trips**: `parse ∘ print ∘ parse`, and `elaborate ∘ decode ∘ encode ∘ elaborate`.

**The schema generator problem.** Generate-and-filter degenerates to "the compiler rejected it" and tests nothing. Generate a `SchemaRecipe` and interpret it into `(Schema, Model)`; shrink the recipe, never the schema. Build constructively and root-first: namespaces, then the type universe in dependency order, then root tables (key containing no same-family FK), then dependents topologically, each with a `:>` to an already-emitted table and a key headed by that FK — which makes the rooted-key rule hold *by construction*. Asserts are generated by walking the FK graph already built, so anchoring holds by construction too; generate unanchored ones separately as negatives. The load-bearing choice is that the generator is a **model**: it knows each table's shard root, effective field set, declared and derived keys, each assert's expected variety and `bypass access` membership, and each default's admissibility drawn from `50-validation.md` §B — so properties *compare against a known answer* instead of asserting a tautology. Evolution is a second phase: a commit list (`add table`, `add field with default`, `deprecate`, `add trait`, `redeclare`, `add unique`, `add retain step`) that the model folds. That phase is what exercises the DAG, the effective-field-set rule, Rule A, and prune-pinning.

**Golden parser tests over `docs/`.** Build this before the compiler is finished; it is the highest-value suite in the project and it doubles as the linter the corpus needs while the 31-file rewrite is running. Extract every fenced block, classify by info string, and let a block opt out with `-- ! expect: reject` as its first line, with the golden recording the diagnostic — that turns the review's many deliberately rejected forms into a negative-test suite for free. Make the golden the **printer's** output, so `parse ∘ print ∘ parse` is a tested fixpoint and the printer cannot drift from the parser; that also lets the linter *fix* the 53 known-broken examples rather than only reporting them. Extract the `ebnf` blocks too and check every non-terminal is defined and reachable — that mechanically catches the dangling-reference class the review found by hand (`railroad.md:54` names `[` and `]` with no production). CI gate: the count of blocks that parse may not decrease.

**"Correct" for a distributed component you cannot run multi-node.** Three tiers, and only the first is cheap enough to run on every commit.

1. **Deterministic simulation.** N replicas in one process, virtual clock, an explicitly scheduled message queue, injectable partition/crash/reorder/duplicate, seeded so a failing run replays from its seed alone. This is only possible if the protocols are written as pure `step :: Msg -> Replica -> (Replica, [Msg])` with I/O confined to the storage edge, and if network and clock access go through an abstract interface from the first line of `datacode-server`. The simulator must link the *real* protocol code — a simulator testing a reimplementation tests nothing. Properties: at most one server holds authority per shard per epoch; committed transactions are serialisable; the cluster converges after healing; an elected primary holds every acknowledged write; a bulk mutation's per-shard report is never mistaken for complete when a shard was unreachable (`distribution.md:473`). Keep real LMDB at the storage edge so the 1 107 µs fsync stays honest while the message path stays controlled.
2. **A three-process local cluster** for everything the simulator cannot claim: TCP backpressure and head-of-line blocking, fsync contention on shared hardware, mmap page-cache behaviour, and the actual writer-lock handover stall. Run the DR drill here, scripted.
3. **Real multi-region**, later, for exactly one class of claim: WAN round trip under the synchronous durability class, which dominates the LMDB write cost by three orders of magnitude and which nothing else can measure.

**Benchmarks as gates**, on the four numbers the design's arguments actually rest on: functor apply (0.07–0.8 µs), LMDB read (11 µs), route dispatch (0.2 µs), Servant + `Raw` (1 µs). Each is cited as load-bearing in `tech-stack.md`, so a silent regression invalidates an argument, not just a number. Re-measure all four under `criterion` before quoting them — every sub-millisecond figure in the current spikes prints as `0µs` because the timer is millisecond-resolution, and the 11 µs read carries per-call `runInBoundThread` overhead that production removes.

## G. Where the design is still too vague to code

Each entry names the decision that unblocks it. The first four block the earliest milestones and should be taken before anyone writes code against them.

**G1. The revalidation set's algorithm.** `constraints.md:193-196` obliges an insert into `Suspension` to revalidate the `Invoice` rows that reach it and says the set is "the FK chain traversed backwards". `spikes/functor-dsl`'s `revalidationSet` returns **table names**; the commit path needs rows; nothing computes that; and no storage structure can answer "which rows reference me". There is no bound, no algorithm, and no exclusion rule (`10-findings.md:3959-3966`). *Unblocks on:* declaring `fk_index` **mandatory** — a server-local, derivable, unreplicated LMDB db keyed `(fk_field_schema_node, referenced HeadKey, referencing HeadKey)`, maintained on every insert and delete of a `:>` field — plus three rules: restrict the closure to edges appearing in some assert's path; state whether edges into `Reference` and `Configuration` participate (they must not, or one `Reference` write reaches the connected component); and state what happens above a threshold. The third changes the *shape* of the pipeline, because a threshold rule needs a cost estimate before step 7 runs, not after. A materialization proposal cannot serve a correctness-critical set.

**G2. Name resolution, in full.** This is specified nowhere and it is not merely thin. `Binding ::= Ident` cannot spell `system.auth.ServiceAccount`, which four documents declare. `namespace app.commerce` appears once (`namespaces.md:60`), is not a `Statement`, is not reserved, and is contradicted by two sentences saying namespaces are implicit. `functions.md:83` shows `import Data.Time (UTCTime, diffUTCTime)` — a *Haskell* module import — inside a schema block. The only resolution rule in the corpus is `evolution.md:16`, which covers intra-commit resolution and nothing else. *Unblocks on:* four decisions — how an unqualified top-level declaration acquires its namespace; the lookup order for an unqualified reference in a field type, a trait list and a query source; whether `namespace` is a statement or is deleted; and whether `Binding`/`TypeDecl`/`TraitDecl`/`FunctionDecl` take `QName`. Decide before the lexer, because it decides whether `QName` or a file-level context is the parser's currency, and build the resolver's environment as a *graph position* rather than a global map, because a name resolves at a schema node — retrofitting that after `at` exists is a rewrite.

**G3. The query plan representation.** Nothing anywhere specifies plan terms. `queries.md` specifies semantics thoroughly; `spikes/functor-dsl`'s `Query ctx` is a join chain with only `Exists`/`Count` as eliminators, no row type, no projection, no `group`, no `Table a`. `:explain` is already in the grammar and `system.api.FormatFunctor` transforms query *results*, so a plan has to be a value, not an `IO` action. *Unblocks on:* three decisions — (a) is a plan the elaborated term or a separate IR, and if separate, which analyses run on which; (b) how it is typed, and the answer is almost certainly "indexed by primitive `Ty a` at the leaves with an existential `SomeRow` carrying a runtime `RowTy` at the row level", because a type-level row list forces either singletons for the entire user schema or `unsafeCoerce` at the schema boundary; (c) the carrier for a nested table-valued column — recommend one contiguous child block plus a per-parent `Vector Int` boundary vector at every depth, because it makes `count rows` O(1), makes `rows.field` a column slice, makes a coordinator merge O(parents) rather than O(rows), and is byte-identical to a stored component subtree. Decide (c) before `group` is built; getting it wrong rewrites `group`, materialization, and the result wire format.

**G4. The range tree's schema, and where `Configuration` lives.** The range tree decides which server serves which key range, is invoked as authoritative in three documents, and has no table, no fields, no key, and no type for its heterogeneous bounds (a `Text` username, a `Timestamp` boundary, a 12-byte `DataId`). The cluster shard directory has no root, no primary, and no registration protocol. Underneath both: `Configuration` has no shard and no stated write path, so every server reads the routing table and nobody serialises writes to it. *Unblocks on:* declaring `system.shards.Range`, `system.shards.DurabilityPolicy`, `system.shards.RejoinPolicy`, `system.shards.ConstraintGroup` and `system.graph.Transaction`; deciding how a `RangeBound` is typed (recommend a `KeyDomain k` witness held per shard family, resolved once at schema commit, so runtime comparison is total and only decode can fail); deciding how an unbounded end is spelled without a `Null`-derived variant in a key; and naming the shard that holds `Configuration` and its primary.

**G5. Delete-plus-insert versus the query surface.** `split shard` is contradicted by row-rooting — under "one shard per root row" (`transaction-graph.md:158-161`), splitting at the root table's candidate key cuts a one-element set, while `transaction-graph.md:165` says a split redistributes roots and `distribution.md:64` says the range tree is untouched. `20-syntax-decisions.md:3786` calls this a genuine contradiction and declines to resolve it. *Unblocks on:* naming the three operations an operator actually wants — move a key region to another primary, split a whale's storage without moving authority, rebalance a family — and checking which verb covers each. The gaps are the specification.

**G6. Nine query-semantics gaps that are forks in the parser, not wording.** Clause order and repetition in `QueryClause*` (`railroad.md:603` imposes none; `queries.md:299` and `auth.md:492` both write `where` after a projection that dropped the column it names). `at`'s second coordinate and its default (`storage.md:200-202` pegs a query to a pair; `AtClause` sets one). Which node a `diff` resolves schema, row type and key at. The singleton-query-to-row coercion, which sits on the authentication path and is used in three positions and defined in none. The period-over-period spelling — `><` has no predicate slot, and the shifted self-join is the *sole* stated justification for having no window functions, so it currently cannot be written at all; recommend a `shift`/`lag` function over a `Grain`-keyed table, which costs no grammar and no invariant. Whether `|` is a relational union (claimed twice, admitted by no production, and needed by the rollup union). Parameterised bindings, since `RequestRollup Hour` must be a `Source`. Key propagation over a *set* of candidate keys. And `id` does not exist, while eleven mutation and filter examples project and filter on it.

**G7. The `TxNode` frame's field set.** A frame is the hardest thing in the system to change after the fact, and three things want to be added to it — a checksum (`storage.md` has none at all), a node-kind field (six node shapes are cited as precedent with no field lists anywhere), and the re-key supersession record. That record is a `List(struct)`, i.e. a *pointer* field: `storage.md:186`'s "exactly 8 bytes per message" measured a data-section scalar (`spikes/capnproto/output.txt:89-97`), and a pointer word rides every `TxNode` in the cluster forever. *Unblocks on:* re-running the capnproto spike with a pointer field (one hour), then freezing the field set — checksum algorithm and whether it covers the length prefix, node-kind discriminator as a *field* and never an open union (an old decoder seeing an unknown union tag applies the transaction and silently drops the variant, `50-validation.md:114`), and the supersession record typed over `HeadKey` rather than `DataId`, because a component has no `DataId`.

**G8. What a schema node contains, and what is hashed.** `TxNode.schemaVer` is a 32-byte SHA-256 of the schema graph node and nothing defines the bytes. Related and unanswered: whether a node holds the whole schema state or a delta, given the evolution diff is per field path and per predicate address; how a predicate with **no name** is addressed, since a `where` block with two anonymous lambdas has two indistinguishable predicates and both `enforce … / <name>` and the per-address diff are undefined over them (`types.md:49-54` shows exactly such a block); and whether the schema graph is self-hosted as `system.schema.*` rows or is a bespoke structure with a table-shaped view. *Unblocks on:* writing the canonical form, then deciding whether an anonymous lambda gets a positional address within its block or is rejected in a multi-predicate block — a one-line rule either way.

**G9. The version chain and `log_index`'s value.** See R9 and R11. `storage.md:29` gives `log_index` a whole-log `Word64` offset, which cannot coexist with extents as independently allocated, relocatable files. *Unblocks on:* `(ExtentId, offset, length)` (still 12 bytes, caps an extent at 4 GiB, say so) plus a `version_index` keyed `HeadKey ++ TxSeq`.

**G10. The `Error` carrier and the validation shapes.** `functions.md:74-80` admits `a -> Bool`, `a -> Maybe b` and `a -> Either Error a`; the DSL encodes only the first, and there is no `Error` type anywhere. So "violations as reified failure" has nothing to reify into, and `monitor` — the mandatory default for connector-sourced data — cannot be expressed by a result type that is `Either`. *Unblocks on:* declaring `data Outcome a = Accepted a [Violation] | Rejected Error [Violation]` and an `Error` carrier before the first functor kind is ported. Retrofitting it after connectors exist touches all four kinds and every call site.

**G11. Append-only's real exemption list.** "The `QueueState` field is the one exemption in the whole system" is stated normatively in three files and is false in at least four places — `Violation.state`, `Challenge.state`, `TriggerState.held`, `Queue.scheduled_at`, and arguably `BackoffState`. `system.integrity.Violation` additionally has three authorities (a materialized view, a `LogData` table, and a table you insert into by hand). *Unblocks on:* one authority for `Violation` (recommend the shard-local `LogData` table), a representation for `TriggerState.held` (recommend a server-local derived index outside the graph), and an exemption list that the append-only property test takes as an explicit parameter.

**G12. Ordinal assignment and component depth.** "A read-modify-write against the parent's current maximum" (`transaction-graph.md:487-490`) names no location for the maximum, and "never reused" contradicts `documents.md:104-105`'s "an array node's children are its ordinals" on any shredded-tree rebuild or middle-element delete. Meanwhile `head_index` keys are 12 + 4n bytes against LMDB's 511-byte default limit, and `Doc indexed` shreds *externally supplied* documents, so nesting depth is attacker-controlled. *Unblocks on:* a 4-byte reserved high-water field on the parent for author-written components plus a deterministic position-derived ordinal for shredded nodes (so a rebuild is idempotent), and a `system.config` depth cap well below 124 enforced at shred time, routing a violation rather than failing a connector commit.

**G13. Two decisions taken this month that contradict each other.** Redaction reaches the key while the cursor is built from the last row's ordering tuple (R17). And "any role holder can authenticate" requires a tertiary to mint sessions, while "issuing a session must not be a row write" makes the token a signed bearer — symmetric signing makes every verifier a minter, asymmetric signing makes only key-holders mint, and `auth.md` names no signing key, custody or rotation. *Unblocks on:* for the second, per-server asymmetric keys with the key id in the token and the public-key set replicated, so a compromised server's tokens are revocable by dropping one row.

**G14. Two things that will stall work by being unwritable rather than unclear.** `system.api.GeneratedRoute` cannot be declared in DataCode today — `methods : [HttpMethod]` is a list type with no production (deliberately; a list column is a repeating group), and eleven types it uses are undefined. Recommend a `Component` sub-table of `:> HttpMethod`, which the table-valued `:>` decision now makes the one spelling and which needs no new syntax. And there is no way to resolve a trait field collision by rename since `from` was withdrawn, and no `'*'` in a `TraitBody`, so a trait cannot be evolved additively — adding a field to a trait means restating the whole body, and omission deprecates.
